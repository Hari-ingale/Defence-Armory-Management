"# Armory Management System

A complete full-stack web application for managing military armory operations including soldier registration, weapon issuance, and return tracking.

## 🚀 Features

- **Secure Authentication**: Admin login with bcrypt password hashing
- **Soldier Management**: Register and update soldier records
- **Weapon Issuance**: Issue weapons to registered soldiers with complete tracking
- **Weapon Returns**: Process weapon returns with condition logging
- **Search Functionality**: Quick search for soldier records and weapon history
- **Dashboard Analytics**: Real-time statistics on issued weapons
- **Modern UI**: Clean, responsive design with professional admin panel aesthetics

## 📋 Prerequisites

- **Node.js** (v14 or higher)
- **Oracle Database** (11g or higher)
- **Oracle Instant Client** (for oracledb driver)

### Frontend
- HTML5

- Font Awesome Icons

## 📦 Installation

### 1. Clone or Download the Project

```bash
cd /app/armory-system
```

### 2. Install Backend Dependencies

```bash
cd backend
npm install
```

This will install:
- express
- oracledb
- bcrypt
- cors
- body-parser
- dotenv

### 3. Setup Oracle Database

#### A. Connect to Oracle Database

```bash
sqlplus system/Oracle123@localhost:1521/XE
```

#### B. Run the Database Schema

```sql
@/app/armory-system/database/schema.sql
```

This will create:
- **Tables**: users, soldiers, weapons, weapon_issue
- **Sequences**: weapon_issue_seq
- **Triggers**: Auto-update timestamps
- **PL/SQL Package**: weapon_management_pkg
- **Sample Data**: 3 sample soldiers

#### C. Verify Database Setup

```sql
-- Check tables
SELECT table_name FROM user_tables 
WHERE table_name IN ('USERS', 'SOLDIERS', 'WEAPONS', 'WEAPON_ISSUE');

-- Check package
SELECT object_name, status FROM user_objects 
WHERE object_name = 'WEAPON_MANAGEMENT_PKG';

-- View sample soldiers
SELECT * FROM soldiers;
```

### 4. Configure Environment Variables

The `.env` file is already configured with your Oracle connection details:

```env
PORT=8001
DB_HOST=localhost
DB_PORT=1521
DB_SID=XE
DB_USER=system
DB_PASSWORD=Oracle123
ADMIN_USERNAME=admin
ADMIN_PASSWORD=ad133
```

**Important**: In production, change the admin password and use environment variables!

## 📖 Usage Guide

### 1. Login
- Enter your username and password on the login screen
- Click \"Sign In\" to access the dashboard

### 2. Dashboard Overview
- View total issued weapons count
- Access quick action cards for all operations

### 3. Register Soldier
- Click \"Register Now\" on the Soldier Registration card
- Fill in required fields: Soldier ID, Name, Rank, Unit
- Optional fields: Phone, Email
- Click \"Register Soldier\"
- If soldier exists, record will be updated

### 4. Issue Weapon
- Click \"Issue Weapon\" on the Issue Weapon card
- Enter Soldier ID (must be registered first)
- Enter Weapon ID, Type, and Serial Number
- Optionally specify who issued the weapon
- Click \"Issue Weapon\"

### 5. Return Weapon
- Click \"Return Weapon\" on the Return Weapon card
- Enter Weapon ID
- Select weapon condition (Good, Fair, Damaged, Needs Repair)
- Add optional remarks
- Click \"Return Weapon\"

### 6. Search Soldier
- Click \"Search Now\" on the Search Soldier card
- Enter Soldier ID
- Click \"Search\"
- View soldier details and complete weapon history

## 🗄️ Database Schema

### Tables

#### USERS
- `user_id` (Primary Key, Auto-generated)
- `username` (Unique)
- `password` (bcrypt hashed)
- `role` (ADMIN, OFFICER, USER)
- `created_at`, `updated_at`

#### SOLDIERS
- `soldier_id` (Primary Key)
- `name`, `rank`, `unit`
- `phone`, `email`
- `status` (ACTIVE, INACTIVE, TRANSFERRED)
- `created_at`, `updated_at`

#### WEAPONS
- `weapon_id` (Primary Key)
- `weapon_type`, `serial_number` (Unique)
- `status` (AVAILABLE, ISSUED, MAINTENANCE, RETIRED)
- `created_at`, `updated_at`

#### WEAPON_ISSUE
- `issue_id` (Primary Key, Auto-generated)
- `soldier_id` (Foreign Key)
- `weapon_id` (Foreign Key)
- `issue_date`, `issued_by`
- `return_date`, `returned_by`
- `condition` (GOOD, FAIR, DAMAGED, NEEDS_REPAIR)
- `remarks`

### PL/SQL Procedures

#### weapon_management_pkg.issue_weapon
Issues a weapon to a soldier with transaction management.

Parameters:
- `p_soldier_id`: Soldier identifier
- `p_weapon_id`: Weapon identifier
- `p_weapon_type`: Type of weapon
- `p_serial_number`: Weapon serial number
- `p_issued_by`: Who issued the weapon

#### weapon_management_pkg.return_weapon
Processes weapon return with condition tracking.

Parameters:
- `p_weapon_id`: Weapon identifier
- `p_returned_by`: Who received the weapon
- `p_condition`: Weapon condition
- `p_remarks`: Additional notes

## 🔌 API Endpoints

### Authentication
- **POST** `/api/login`
  - Body: `{ username, password }`
  - Returns: `{ success, message, user }`

### Soldier Management
- **POST** `/api/register-soldier`
  - Body: `{ soldier_id, name, rank, unit, phone?, email? }`
  - Returns: `{ success, message, soldier_id }`

- **GET** `/api/search-soldier/:soldier_id`
  - Returns: `{ success, soldier, weapons[] }`

### Weapon Management
- **POST** `/api/issue-weapon`
  - Body: `{ soldier_id, weapon_id, weapon_type, serial_number, issued_by? }`
  - Returns: `{ success, message, weapon_id, soldier_id }`

- **POST** `/api/return-weapon`
  - Body: `{ weapon_id, condition, returned_by?, remarks? }`
  - Returns: `{ success, message, weapon_id }`

- **GET** `/api/total-issued`
  - Returns: `{ success, total }`

### Combined Operations
- **POST** `/api/fetch-and-issue`
  - Body: `{ soldier_id, weapon_id, weapon_type, serial_number, issued_by? }`
  - Returns: `{ success, message, soldier_id, weapon_id }`

### Health Check
- **GET** `/api/health`
  - Returns: `{ status, message }`

## 🐛 Troubleshooting

### Oracle Connection Issues

If you encounter Oracle connection errors:

1. **Check Oracle Service**
   ```bash
   lsnrctl status
   ```

2. **Verify Connection String**
   ```bash
   sqlplus system/Oracle123@localhost:1521/XE
   ```

3. **Check Oracle Instant Client**
   ```bash
   node -e \"console.log(require('oracledb').versionString)\"
   ```

### Backend Issues

1. **Port Already in Use**
   ```bash
   # Find process using port 8001
   lsof -i :8001
   # Kill the process
   kill -9 <PID>
   ```

2. **Dependencies Issues**
   ```bash
   cd backend
   rm -rf node_modules package-lock.json
   npm install
   ```

### Common Errors

- **\"Soldier not found\"**: Register the soldier before issuing weapons
- **\"Weapon already issued\"**: Return the weapon first before reissuing
- **\"No active issue found\"**: The weapon must be issued before it can be returned
- **Login failed**: Check username and password (default: admin/ad133)

## 📊 Database Queries

### Useful Queries

```sql
-- View all issued weapons
SELECT wi.*, s.name, w.weapon_type
FROM weapon_issue wi
JOIN soldiers s ON wi.soldier_id = s.soldier_id
JOIN weapons w ON wi.weapon_id = w.weapon_id
WHERE wi.return_date IS NULL;

-- Weapons in maintenance
SELECT * FROM weapons WHERE status = 'MAINTENANCE';

-- Soldier weapon count
SELECT s.soldier_id, s.name, COUNT(wi.issue_id) as weapon_count
FROM soldiers s
LEFT JOIN weapon_issue wi ON s.soldier_id = wi.soldier_id
GROUP BY s.soldier_id, s.name;

-- Recent activity
SELECT * FROM weapon_issue
ORDER BY issue_date DESC
FETCH FIRST 10 ROWS ONLY;
```
